# 05 · Как пустить Linux-сервер и инструменты командной строки через линию

В Linux есть два пути к линии — выбирайте по задаче. Если через неё должен идти весь компьютер (скачивание образов Docker, сервисы, которым нужна зарубежная сеть, работа без присмотра), используйте OpenVPN: один файл конфигурации в /etc/openvpn/client/ и автозапуск при загрузке. Если через неё должны идти лишь несколько команд (git, pip, npm, curl), используйте «Веб Прокси»: адрес прокси в переменной окружения http_proxy, а остальной трафик не затрагивается. На десктопном Linux можно также импортировать конфигурацию в NetworkManager. В статье разобраны все три варианта, а также как оформить файл с паролем и какими командами проверять.

## Путь первый: весь компьютер через линию (OpenVPN)

1. Установите клиент: Debian / Ubuntu sudo apt install openvpn, Fedora sudo dnf install openvpn, Arch sudo pacman -S openvpn.
2. Войдите на этот сайт и на странице OpenVPN нажмите на флаг региона, чтобы скачать .ovpn. В конфигурацию для Linux аккаунт и пароль не встроены (NetworkManager не принимает файлы со встроенными учётными данными), поэтому создайте отдельный файл с паролем: две строки, в первой email от этого сайта, во второй пароль, chmod 600.
3. Скопируйте .ovpn в /etc/openvpn/client/<region>.conf и допишите в файле путь к файлу с паролем после auth-user-pass.
4. sudo systemctl enable --now openvpn-client@<region>. Состояние проверяйте через systemctl status openvpn-client@<region>, а что curl -s https://ipinfo.io/country показывает выбранный регион — сверьте.
5. Чтобы сменить регион, скачайте другую конфигурацию и включите другой юнит; одновременно запускайте только один.

## Путь второй: через линию только инструменты командной строки («Веб Прокси»)

Адрес прокси со страницы «Прокси» этого сайта вместе с аккаунтом и паролем можно сразу прописать в переменные окружения: export https_proxy=https://username:password@proxy-address export http_proxy=$https_proxy. Спецсимволы в пароле нужно закодировать для URL. После этого curl, wget, git, pip и npm в этом терминале идут через линию, а другие программы не затрагиваются.

Демон Docker не читает переменные окружения оболочки; пропишите их в Environment= в /etc/systemd/system/docker.service.d/proxy.conf и перезапустите docker. Для apt пропишите Acquire::https::Proxy в /etc/apt/apt.conf.d/proxy.conf.

На этом пути по самой схеме нет соединения, которое могло бы оборваться; root не нужен, маршруты не меняются. Подходит для корпоративных серверов и случаев, когда нужно только ускорить скачивание; действует только на программы, которые учитывают переменные прокси, остальной трафик не затрагивается.

## Путь третий: NetworkManager на десктопном Linux

1. Установите network-manager-openvpn-gnome (на странице OpenVPN этого сайта центр приложений открывается одним нажатием).
2. «Параметры» → «Сеть» → VPN → «+» → «Импортировать из файла», выберите .ovpn, введите email и пароль от этого сайта и сохраните.
3. Включайте и выключайте VPN с верхней панели или из трея. Чтобы подключаться автоматически при загрузке, в настройках проводного/беспроводного подключения отметьте «Автоматически подключаться к VPN» (Automatically connect to VPN).

## Проверка и устранение неполадок

- Проверьте выход: страна в curl -s https://ipinfo.io — выбранный регион.
- Проверьте DNS: в resolvectl status у интерфейса VPN должен быть DNS, переданный линией; если есть утечка, добавьте в конфигурацию dhcp-option DNS или используйте скрипт update-systemd-resolved.
- AUTH_FAILED: неверный файл с паролем или срок аккаунта истёк; если меняли пароль, обновите файл с паролем.
- Таймаут TLS-рукопожатия: UDP до сервера не проходит; смените регион или сеть. На облачном сервере в группе безопасности нужно разрешить исходящий UDP.
- Сервер в Китае, и китайские источники должны идти напрямую: после подключения OpenVPN весь исходящий трафик идёт через линию. Переключите источники apt / pip / npm на китайские зеркала или используйте второй путь, чтобы через линию шли только конкретные команды.

## Что нужно знать

- Один Linux-компьютер считается одним устройством и делит лимит одновременных подключений с остальными вашими устройствами («Личный» — 2 устройства, «Семейный» — 4, «Корпоративный» — 8); «Веб Прокси» из второго пути считается по подключениям и тоже входит в лимит.
- Файл конфигурации и файл с паролем равноценны вашему аккаунту; не коммитьте их в git-репозиторий и не кладите в образы.
- После смены пароля старая конфигурация сразу перестаёт работать — так задуман механизм отзыва доступа. Достаточно обновить файл с паролем.
- Запуская линию на облачном сервере, соблюдайте условия использования провайдера; линия записывает только длительность подключения и общий объём трафика.

## Частые вопросы

**Почему в конфигурацию для Linux не встроены аккаунт и пароль?** NetworkManager при импорте не принимает файл со встроенными учётными данными и выдаёт ошибку импорта, поэтому в версии для Linux их нужно вписать самому; при использовании systemd — в файл с паролем.

**Можно ли пустить через линию только Docker?** Да: задайте переменные прокси только для демона Docker (второй путь) или запустите контейнер с OpenVPN внутри (gluetun), чтобы через линию шли конкретные контейнеры.

**А «Приватная» сеть (Tailscale) на Linux?** Официальный скрипт ставит её одной строкой, а войти можно командой tailscale up --login-server=<управляющий сервер этого сайта>. Подходит, если к этой машине нужно подключаться снаружи или хочется настроить один раз и всегда быть онлайн; чтобы просто ускорить скачивание, проще OpenVPN или прокси.

**А OpenWrt на роутере — так же?** В OpenWrt установите luci-app-openvpn и загрузите .ovpn — и вся локальная сеть пойдёт через линию; роутеру с прошивкой этого сайта это не нужно, достаточно войти в аккаунт.
